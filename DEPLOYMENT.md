# Развёртывание на PHP-хостинге

Перед покупкой тарифа подтвердите PHP 8.2+, PDO MySQL, mbstring, fileinfo, GD (JPEG/PNG/WebP), OpenSSL, Composer для локальной сборки, MySQL/MariaDB с InnoDB и max_allowed_packet от 16 МБ, PHP CLI + Cron, SMTP с TLS, HTTPS, закрытую папку вне public_html, поддержку .user.ini (enable_post_data_reading=0) и доступ к ClamAV INSTREAM для вложений. SSH для сайта не обязателен: пакет загружается через файловый менеджер; экспорт файлов потребует закрытого административного доступа к PHP CLI или отдельного инструмента. Если у тарифа нет ClamAV, отправляйте заявки без вложений.

Сборка на компьютере: npm ci; composer install --working-dir=backend --no-dev; npm run package. Пакет находится в deploy/shared-hosting. Содержимое public_html публикуется как корень домена; private размещается рядом и закрывается от веб-доступа. Не выкладывайте исходный каталог проекта целиком. Установите HTTPS, настройте заголовки безопасности и статический кеш в Apache или эквиваленте панели хостинга. PHP-конфигурация и approved документы должны быть вне public_html.

Создайте отдельную БД и пользователя. После резервной копии и отдельного разрешения владельца выполните вручную php private/backend/bin/console.php migrate --apply. Эта схема не переносит старые данные PostgreSQL. Копируйте config.example.php в private/backend/config.local.php; задайте точный origin, случайный secret минимум 32 символа, db, утверждённые policy/consent и версии, согласованный retention_days, smtp.project_manager_email, параметры SMTP, scanner. До готовности сохраняйте enabled=false. Не используйте msk@form-resurs.ru как получателя по умолчанию.

Cron раз в минуту: php /absolute/private/backend/bin/console.php notifications. Очистка истёкших данных: php /absolute/private/backend/bin/console.php cleanup раз в час. Задачи ограничены десятью за запуск, количество попыток ограничено конфигурацией. Успешный статус означает принятие письма SMTP, не прочтение.

Для локальной разработки можно установить PHP и MySQL через Homebrew, создать отдельную тестовую БД и запустить встроенный PHP-сервер на собранном public_html с enable_post_data_reading=0. Next dev работает отдельно для фронтенда; тестирование формы проводите через локальный PHP-сервер того же origin. Используйте тестовую почту и не включайте форму с реальными данными. Виртуальный хостинг может требовать индивидуального пути к PHP CLI и иной настройки upload/post_max_size, memory_limit=256M, max_execution_time=60, ограничения тела запроса от 21 МБ.

При сбое восстановите шифрованную резервную копию MySQL, конфигурации и утверждённых документов на тестовой среде, проверьте количество заявок и SHA-256 файлов, затем переключайте сайт. Включайте экспортированные файлы и копии писем в утверждённую процедуру удаления. Запретите внешний доступ к БД. После публикации проверьте страницы, HTTPS, /api/inquiries/settings/, работу формы, cron и SMTP на тестовых данных без отправки настоящим клиентам.
