# Форм-Ресурс М — V2

Next.js App Router, TypeScript, PostgreSQL и Prisma. Существующие страницы и визуальная система сохранены. Заявки принимает настоящий Route Handler. Сборка V1 в каталоге out больше не используется.

## Требования

Node.js 24 LTS, npm, PostgreSQL 17 или совместимая поддерживаемая версия, постоянный закрытый диск для вложений. В production нужны HTTPS, обратный прокси, антивирус ClamAV с clamdscan и планировщик задач.

Хранилище рассчитано на POSIX-права Linux/macOS. Для production используйте Linux. dev запускается через Webpack. Если в ограниченной среде недоступны файловые наблюдатели, используйте WATCHPACK_POLLING=true npm run dev.

Приложение требует работающего Node.js сервера. GitHub Pages и обычная раздача статического out для V2 не подходят. Для нескольких экземпляров приложения обязательна общая PostgreSQL. Новые файлы хранятся в BYTEA, локальный закрытый каталог нужен для временной проверки антивирусом и старых файлов до отдельного согласованного переноса.

## Установка и база

Установите зависимости через npm ci. Скопируйте .env.example в .env и задайте собственные значения. Не сохраняйте .env в Git.

Для локальной PostgreSQL через Docker задайте POSTGRES_PASSWORD и соответствующий DATABASE_URL в .env:

~~~bash
docker compose up -d postgres
npm ci
npm run db:generate
npm run db:migrate
npm run dev
~~~

Пароль в DATABASE_URL должен быть URL-кодирован. Для локального теста проще использовать случайную шестнадцатеричную строку, созданную openssl rand -hex 32. Docker публикует PostgreSQL только на 127.0.0.1:5432. Не открывайте порт базы в Интернет.

Если PostgreSQL уже установлена, создайте отдельные базу и пользователя и укажите DATABASE_URL. В production отделите пользователя миграций от пользователя приложения. Приложению нужны операции с таблицами заявок, уведомлений, лимитов и аудита, а не права суперпользователя или создания баз.

db:migrate выполняет prisma migrate deploy для уже сохранённых миграций. Для изменения схемы в разработке используйте npm run db:dev -- --name имя_изменения. Генерация Prisma не требует доступной базы.

## Конфигурация

Все параметры находятся на сервере. Префикс NEXT_PUBLIC для секретов не используется.

| Параметр | Назначение |
| --- | --- |
| DATABASE_URL | Соединение PostgreSQL |
| APP_ORIGIN | Точный origin формы, без конечного слеша, в production только HTTPS |
| SITE_URL, SITE_INDEXABLE | Канонический адрес и разрешение индексации |
| INQUIRIES_ENABLED | Включение приёма, по умолчанию false |
| FORM_SECRET | Случайный секрет не короче 32 символов, создайте openssl rand -hex 32 |
| CLIENT_IP_HEADER | Пусто для общего лимита всех клиентов, x-real-ip за доверенным прокси |
| UPLOAD_DIR | Закрытый каталог временной проверки и совместимости со старыми файлами; не публиковать |
| UPLOAD_MAX_FILES | Количество файлов, по умолчанию 5 |
| UPLOAD_MAX_FILE_MB | Размер одного файла, по умолчанию 10 МиБ |
| UPLOAD_MAX_TOTAL_MB | Суммарный размер, по умолчанию 20 МиБ |
| UPLOAD_FORMATS | Подмножество jpg,png,webp,pdf |
| UPLOAD_SCAN_REQUIRED | Обязательная антивирусная проверка, в production по умолчанию true |
| CLAMDSCAN_PATH | Абсолютный путь к clamdscan |
| INQUIRY_RETENTION_DAYS | Явный согласованный срок хранения; без него форма отключена |
| RATE_LIMIT_WINDOW_SECONDS | Окно ограничения одного клиента, по умолчанию 900 секунд |
| RATE_LIMIT_MAX_REQUESTS | Число попыток за окно, по умолчанию 5 |
| RATE_LIMIT_GLOBAL_PER_MINUTE | Общий предел попыток отправки, по умолчанию 30 в минуту |
| PRIVACY_POLICY_PATH, PRIVACY_CONSENT_PATH | Пути к двум утверждённым текстовым документам UTF-8 |
| PRIVACY_POLICY_VERSION, PRIVACY_CONSENT_VERSION | Версии утверждённых документов |
| SMTP_HOST, SMTP_PORT, SMTP_SECURE | SMTP, по умолчанию порт 587 и обязательный STARTTLS, true для TLS при подключении |
| SMTP_USER, SMTP_PASSWORD | Учётные данные SMTP |
| SMTP_FROM | Адрес отправителя |
| PROJECT_MANAGER_EMAIL | Адрес проектного менеджера, пока пустой |
| MANAGER_EMAIL | Устаревший резервный параметр; удалить при переходе |
| LEGAL_DOCUMENTS_APPROVED | true только после утверждения документов |
| SMTP_ATTACHMENT_MAX_MB | Лимит MIME-размера письма с вложениями, по умолчанию 10 МиБ |
| NOTIFICATION_MAX_ATTEMPTS | Число попыток очереди, по умолчанию 8 |

Для включения необходимы INQUIRIES_ENABLED=true, DATABASE_URL, FORM_SECRET и оба утверждённых документа с версиями. До их настройки интерфейс отключён, API возвращает 503. Изменение секретов и настроек требует перезапуска процесса. Документы читаются на сервере, их содержимое не принимается от клиента.

## Форма и API

Форма включает имя, предприятие, телефон, email, одну из четырёх услуг, описание, необязательные файлы и отдельное согласие. Ограничения проверяются в браузере и повторно на сервере через Zod. Успех показывается только после подтверждённой записи в PostgreSQL.

GET /api/inquiries/token/ выдаёт подписанный токен для случайного ключа формы. POST /api/inquiries/ принимает multipart/form-data. Проверяются точный Origin, ограничения запросов, токен, срок его действия, минимальное время заполнения и скрытое поле ловушки. Тело запроса ограничивается по реально прочитанным байтам и времени, а не только Content-Length.

Ключ формы обеспечивает идемпотентность. При потерянном ответе повторите отправку с теми же данными и файлами в той же форме. Сохранённая заявка будет подтверждена повторно. Изменённые данные с уже использованным ключом получают 409. Сохраняйте форму до получения результата, обновление страницы создаёт новый ключ.

Лимиты хранятся в PostgreSQL и работают между процессами. Недоступная база приводит к отказу приёма, ограничения не обходятся. При пустом CLIENT_IP_HEADER все посетители делят один консервативный лимит. Для production обратный прокси должен заменять x-real-ip реальным адресом TCP-клиента и закрывать прямой доступ к Node.js. Нельзя доверять заголовку, предоставленному самим посетителем. Для распределённых ботнетов дополнительно нужны ограничения соединений и запросов на прокси.

## Вложения

Разрешены только перечисленные форматы. SVG, архивы, исполняемые файлы, Office с макросами и произвольные CAD-файлы не принимаются. Для неподдерживаемой документации согласуйте отдельный защищённый канал.

Проверяются расширение, MIME и сигнатура. Изображения полностью декодируются с ограничением 20 млн пикселей и записываются заново без исходных метаданных. PDF разбираются, ограничиваются 100 страницами, зашифрованные документы и активные элементы отклоняются. Это проверка структуры, не гарантия отсутствия вредоносного содержимого.

В production включите ClamAV, запустите clamd и задайте CLAMDSCAN_PATH. Используется clamdscan --no-summary --fdpass. Нужен Unix-сокет clamd и подходящие права доступа к нему. Ошибка или отсутствие обязательного сканера блокирует файлы. Обращение без вложений можно сохранить. Для локальных синтетических тестов разрешено UPLOAD_SCAN_REQUIRED=false.

Имена на диске генерируются сервером. Каталоги создаются с правами 0700, файлы с 0600. Исходные имена сохраняются только как метаданные. Каталог нельзя размещать в public, out, .next, подключать к статической раздаче или открывать через nginx alias. У приложения нет публичного API чтения заявок или скачивания документов.

UPLOAD_DIR должен быть отдельным закрытым каталогом с правами 0700. При первой инициализации он должен быть пустым. Приложение создаёт служебную метку хранилища и отказывается использовать посторонний непустой каталог.

## Доступ менеджера и обслуживание

Доступ выполняется через SSH с отдельными ключами и правами на сервере. Веб-авторизация сотрудников и админ-панель в V2 не реализованы. Серверные команды запускайте из корня полной установленной копии проекта под уполномоченной учётной записью:

~~~bash
npm run inquiries -- list
npm run inquiries -- show UUID_ЗАЯВКИ
npm run inquiries -- file UUID_ЗАЯВКИ UUID_ФАЙЛА /закрытый/каталог/document.pdf
npm run inquiries -- delete UUID_ЗАЯВКИ
npm run inquiries -- notifications
npm run inquiries -- retry-notifications
npm run inquiries -- cleanup
~~~

list показывает последние 50 обращений без контактных данных. show выводит персональные данные только в защищённую операторскую консоль. Не перенаправляйте этот вывод в общедоступные логи. file проверяет принадлежность файла заявке и контрольную сумму, создаёт новый файл без перезаписи. Операции чтения и удаления фиксируются в AccessAudit. Идентификация оператора обеспечивается индивидуальными SSH-учётными записями и журналом SSH.

Настройте запуск notifications раз в минуту, cleanup раз в час. CLI загружает .env и .env.local через Next.js. Для cron укажите полный путь к node/npm, рабочий каталог и защищённое окружение. Эти процессы требуют полной установки зависимостей, включая tsx. При деплое только standalone-папки отдельно установите и разместите CLI и его зависимости.

cleanup удаляет просроченные заявки и файлы, затем старые счётчики лимитов, аудит и оставшиеся без записи каталоги старше суток. Если удаление файлов не удалось, запись остаётся для повторной очистки, доступ к ней уже закрыт по expiresAt. При неопределённом исходе записи в БД файлы сохраняются до сверки, чтобы не удалить вложения уже принятой заявки. Ручная команда delete поддерживает удаление по обращению субъекта данных.

Сроки резервных копий, копий экспортированных документов и журналов прокси настраиваются отдельно. Параметр срока хранения влияет на новые заявки. Для изменения срока существующих данных требуется отдельная согласованная операция.

## Email

Заявка и запись Notification создаются одной операцией Prisma в PostgreSQL. После сохранения уведомление обрабатывает отдельный планировщик. При отсутствии SMTP статус NOT_CONFIGURED, при ошибке RETRY, после восьми неудачных попыток FAILED. Пользователь получает подтверждение сохранения независимо от SMTP. Планировщик повторяет отправку с задержкой. retry-notifications повторно ставит неотправленные уведомления в очередь.

Письмо содержит номер, дату, имя, организацию, телефон, email, услугу и задачу. Документы прикладываются в пределах лимита MIME-размера; для больших файлов используются инструкции доступа по индивидуальной SSH-учётной записи. Используйте согласованный компанией SMTP, настройте SPF, DKIM и DMARC. Сертификаты TLS проверяются, отключение проверки сертификата не предусмотрено. Для своей CA настройте доверие через NODE_EXTRA_CA_CERTS.

Уведомления имеют семантику «как минимум один раз». При разрыве связи после принятия письма SMTP-сервером возможен повтор. Стабильный Message-ID помогает получателю распознавать такие письма.

## Production

~~~bash
npm ci
npm run db:generate
npm run db:migrate
npm run lint
npm run typecheck
npm test
npm run build
npm start
~~~

Node.js размещайте за HTTPS-прокси на закрытом порту. Ограничьте размер запроса на прокси значением UPLOAD_MAX_TOTAL_MB плюс 128 КиБ, время чтения, количество одновременных соединений и запросов. Например, для новых значений по умолчанию допустим лимит 21m. Не журналируйте тело запроса, заголовки с секретами или контакты. API возвращает безопасные сообщения и случайный номер диагностики, внутренние ошибки не включаются в ответ.

Сборка создаёт .next, включая standalone. При запуске node .next/standalone/server.js скопируйте public и .next/static в соответствующие каталоги standalone, как требует Next.js. Файлы политики, закрытое хранилище и переменные окружения должны быть доступны процессу отдельно.

## Персональные данные и РФ

Перед публикацией компания должна определить оператора, цель и состав данных, утвердить политику, отдельное согласие и сроки хранения, проверить необходимость уведомления Роскомнадзора и организовать обработку отзыва согласия и обращений субъектов. В проекте нет фиктивного готового юридического документа.

Для сбора данных граждан РФ размещайте базу, файловое хранилище и резервные копии в РФ, проверьте договоры с хостингом и почтовым провайдером и условия трансграничной передачи. Основание для проверки — статьи 9, 18, 18.1, 19, 21 и 22 [152-ФЗ на сайте Минтруда](https://mintrud.gov.ru/docs/laws/130). Техническая реализация не заменяет организационные меры оператора.

При сохранении фиксируются время согласия, версии, хеши и снимки обоих документов. Чекбокс не отмечается заранее. Нет аналитики или сторонней CAPTCHA, передающей посетительские данные внешним сервисам.

## Структура и проверки

- src/app/api/inquiries — Route Handlers.
- src/server — конфигурация, Prisma, ограничения, файлы, документы, уведомления и очистка.
- src/lib/inquiry-schema.ts — общая валидация и разрешённые форматы.
- prisma — схема и миграции.
- scripts/inquiries.ts — доступ по SSH и обслуживание.
- tests — проверки защитных механизмов и интеграционные сценарии.

npm test выполняет локальные тесты. Для интеграционного запуска нужна отдельная одноразовая PostgreSQL с именем базы, заканчивающимся на _test, и TEST_DATABASE_URL. Команда npm run test:integration применяет миграции и проверяет работу с синтетическими данными. Для проверки SMTP задайте TEST_SMTP_CERT и TEST_SMTP_KEY, доверие к тестовому сертификату задаётся через NODE_EXTRA_CA_CERTS до запуска процесса. Реальная почта компании при тестировании не используется.

Состояние реально выполненных проверок и оставшиеся ограничения фиксируются в V2_REPORT.md.
